# 校园集市 · 演示与答辩脚本

> 目标时长：6–8 分钟。建议准备两个浏览器窗口：窗口 A 用普通模式，窗口 B 用无痕模式，方便同时演示「卖家」和「买家」。

## 0. 演示前 2 分钟检查

```bash
cd campus-market
python seed.py --reset
python run.py
```

打开 <http://127.0.0.1:5000>，确认：

- 首页有 28 件商品（公开可见 24 件）。
- 登录页可用；管理员账号可用。
- 准备一张本地图片用于上传（`docs/screenshots/` 中任意 PNG 也可）。

演示账号：

| 角色 | 学号 | 密码 |
|---|---|---|
| 管理员 | `admin` | `Admin@12345` |
| 学生 A（卖家） | `2023001` | `Demo@12345` |
| 学生 B（买家） | `2023002` | `Demo@12345` |

## 1. 开场（0:00–0:40）

**讲：**

> 校园二手群最大的问题不是没有商品，而是信息不可信：已经卖出的东西还在刷屏，买家反复问，卖家反复解释。我们的项目把「商品状态」做成系统的核心，而不是附属字段。

打开首页，指出：

- 浅蓝白的校园公告栏风格。
- 右侧「状态一目了然」卡片：在售 / 已售 / 暂停。
- 平台数据：26 件闲置、3 位同学、6 件已售。
- 7 个校园高频分类。

点击右上角 `EN`，页面切到英文；再点 `中文` 切回。说明所有系统文案、校验、后台都支持双语。

## 2. 发布一件闲置（0:40–2:00）

窗口 A：

1. 点击「登录」，使用 `2023001 / Demo@12345`。
2. 点击导航「发布闲置」。
3. 填写：
   - 名称：`宿舍小风扇`
   - 分类：`生活用品`
   - 售价：`15`
   - 原价：`39`
   - 成色：`8成新`
   - 交易地点：`宿舍楼下`
   - 描述：`USB 充电，三档风力，用了一个夏天，功能正常。`
4. 上传 1–2 张本地图片（可选 `docs/screenshots/` 中的 PNG）。
5. 点击「发布」。

**讲：**

> 新发布默认「在售」。图片在服务端会校验扩展名、文件头和 5 MB 上限，文件名用 UUID 重写，避免路径穿越和重名。

发布成功后跳到详情页，指出：状态标签、价格、原价、分类、成色、地点、浏览量、卖家信息。

## 3. 买家浏览与联系（2:00–3:00）

窗口 B（无痕）：

1. 打开首页，点击「全部商品」。
2. 搜索 `风扇`，或按分类 / 价格排序。
3. 打开刚发布的商品。
4. 未登录时显示「登录后查看联系方式」；点击登录，使用 `2023002 / Demo@12345`。
5. 返回详情，联系方式出现。

**讲：**

> 联系方式只在「在售 + 已登录」时显示。这样既保护卖家隐私，也避免已售商品继续被咨询。

在列表页演示筛选：分类、状态、排序、分页；指出分类卡片数量与列表数量一致。

## 4. 成交：切换为已售（3:00–4:00）

窗口 A：

1. 回到商品详情（或「我的发布」）。
2. 状态下拉选择「已售」，点击「更新状态」。

窗口 B 刷新详情：

- 卡片 / 详情灰化，状态「已售」。
- 提示「该商品已售出，不再接受新的咨询」。
- 联系方式消失。

**讲：**

> 已售商品不删除，保留记录，但系统强制隐藏联系方式、禁止新增收藏。它解决的就是「已售还被反复问」的问题。

窗口 A 再切回「在售」，说明买家反悔时可以重新上架。

## 5. 暂停出售（4:00–4:40）

窗口 A：状态改为「暂停出售」。

窗口 B：

- 刷新「全部商品」，商品消失。
- 直接访问详情 URL，显示「暂不出售」，联系方式隐藏。

**讲：**

> 暂停是「临时下架」，不是删除。卖家在「我的发布」仍能看到并恢复；公开用户看不到列表，但直达链接会看到礼貌提示，不会死链。

## 6. 管理员后台（4:40–6:10）

窗口 A 退出登录，使用 `admin / Admin@12345` 登录，进入「后台管理」。

1. **概览**：用户、商品、在售 / 已售 / 暂停、总浏览、待处理举报、分类分布。
2. **商品管理**：
   - 找到一件商品，填写原因「演示下架」，点击「下架」。
   - 窗口 B 刷新，商品 404。
   - 回到后台，点击「恢复」，窗口 B 刷新恢复。
3. **举报处理**：
   - 打开「举报处理」，看到种子数据中的待处理举报。
   - 点击「下架并处理」：商品被管理员下架，举报状态变为已处理。
4. **分类管理**：
   - 新增一个分类（如 `music / 乐器 / Instruments`），或停用「其他闲置」。
   - 说明停用后不在首页 / 发布下拉出现，但历史商品仍可访问。

**讲：**

> 管理员下架和卖家删除是两种不同的软删除：管理员下架可恢复，卖家删除不可恢复。这样既保留审计记录，也尊重卖家的意愿。

## 7. 个人中心与收藏 / 历史（6:10–7:00）

窗口 B（学生 B）：

1. 点开一件在售商品，点击「收藏」。
2. 进入「我的收藏」，看到商品；把已售 / 失效商品也指出来（种子数据含失效收藏）。
3. 进入「浏览记录」，说明暂停 / 下架商品会自动隐藏。
4. 进入「个人中心」，展示昵称、联系方式、密码修改和统计。

**讲：**

> 收藏保留失效条目，方便用户清理；浏览记录只保留仍可访问的商品，避免展示一堆死链。两者策略不同，是按使用场景做的取舍。

## 8. 收尾（7:00–8:00）

**讲：**

> 这个项目的技术栈很轻：Flask + SQLite + Jinja2 + 原生 CSS/JS，没有 npm、没有 CDN、没有外部服务。它不是一个功能堆砌的电商，而是围绕「状态可信」做窄而深的校园工具。我们用 85 个自动化测试覆盖认证、权限、上传、状态、软删除、搜索分页、双语和后台流程，并用桌面端与 375px 移动端截图验证布局。
>
> 下一步会接入学校 SSO、站内消息与通知、图片压缩，并在真实用户中评估「无效咨询下降」和「发布耗时」。

## 9. 常见提问与回答

**Q1：为什么用 Flask + SQLite，而不是 React / Spring / MySQL？**  
A：页面以表单和列表为主，服务端渲染足够；SQLite 零配置、单文件，适合课程演示和 SQL 讲解；Flask 代码量小，权限、CSRF、状态机都能逐行讲清楚。数据量增长后可迁移 PostgreSQL，路由和查询层基本不变。

**Q2：CSRF 是怎么做的？**  
A：会话级 token，服务端在 `before_request` 生成；所有 POST 表单带隐藏字段；提交时用 `hmac.compare_digest` 比较，缺失或错误返回 400。登录成功会清空会话并重建 token，降低会话固定风险。

**Q3：状态机制怎么减少无效咨询？**  
A：状态不是装饰，而是权限开关：已售隐藏联系方式、禁止新增收藏；暂停从公开列表移除；下架直达 404。买家看到的状态就是当前可交易状态。

**Q4：为什么已售不删除？**  
A：保留交易记录和浏览量，便于复盘；同时灰化展示，证明平台有真实成交。删除会让历史信息消失。

**Q5：管理员下架和卖家删除有什么区别？**  
A：两者都是软删除（`is_removed=1`），但 `removed_by` 区分来源。管理员下架可恢复；卖家删除不可恢复，管理员只能只读查看。这样避免后台「复活」卖家不想卖的商品。

**Q6：怎么保证只有校内学生？**  
A：当前用学号注册，属于课程项目的简化；真实场景需要接入学校 SSO 或校园邮箱验证，这是报告里明确写出的局限和未来工作。

**Q7：图片安全怎么处理？**  
A：校验扩展名 + 文件头 + 5 MB 上限；文件名用 UUID；只接受 jpg/png/webp；保存目录固定；删除时只允许 `uploads/` 下的文件名，阻止路径穿越。

**Q8：双语怎么实现？**  
A：`app/i18n.py` 维护中英文字典，模板和 Python 共用 `t()`；语言写入会话；分类、成色、状态、地点、后台、错误页全部映射；用户发布内容保持原文。

**Q9：怎么测试的？**  
A：pytest + Flask test client + 临时 SQLite；85 个测试覆盖认证、CSRF、权限、图片、状态、软删除、搜索分页、收藏历史、后台、双语和页面冒烟。另有 1440px / 375px 浏览器截图与脚本检查。

**Q10：如果并发量很大怎么办？**  
A：当前是单机 SQLite，适合课程与小型部署。扩展路径：PostgreSQL + 连接池、缓存热门列表、图片对象存储与 CDN、异步任务、限流与审计日志。状态切换需要事务与幂等设计。

**Q11：为什么没有聊天和支付？**  
A：范围控制。校园二手交易大多线下完成；聊天和支付会引入消息、订单、退款、风控等大量复杂度。当前优先把「状态可信」做扎实。

**Q12：这个项目最难的部分是什么？**  
A：状态、软删除、权限三者的组合边界。比如暂停商品对公开用户和卖家的可见性不同；管理员下架后卖家能看原因但不能编辑；卖家删除后管理员只能只读。我们用 `item_access_mode()` 统一这些规则，并用测试固定。

**Q13：如果老师让你现场改一个需求？**  
A：可以从「新增一个状态」或「分类增加排序字段」入手，展示模型、路由、模板、测试的改动路径；也可以把「已售」改成「已预订」，只需扩展枚举与文案。

## 10. 演示失败时的备用方案

1. **端口占用**：结束占用 5000 的进程，或修改 `run.py` 端口。
2. **上传失败**：改用种子商品演示状态切换；图片不是核心。
3. **页面样式异常**：强制刷新（Ctrl+F5）；确认 `static/` 未被移动。
4. **数据库状态混乱**：停止服务，执行 `python seed.py --reset`，重启。
5. **时间不够**：只演示「发布 → 已售 → 暂停 → 管理员下架 / 恢复 → 举报」五步。
6. **无法现场运行**：使用 `docs/screenshots/` 中的截图按同样顺序讲解。
